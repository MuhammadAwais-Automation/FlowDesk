# Brain v3 — FlowDesk's memory, run entirely through MCP

Status: built 2026-10-09 (P0-P8). Code: `electron/brain/operator/` (store, ops,
documents), `electron/operator/` (ledger capture, background jobs, operator kit),
gateway `brain.*` / `jobs.*` RPCs, MCP tools in `bin/flowdesk-mcp.mjs`, UI in
`src/pages/BrainHub.tsx`, skills `brain-protocol`, `content-life-path`,
`background-jobs`, `weekly-review`.

Changed 2026-10-11 (the user's call): no review queue. Agents keep Brain through
MCP and what they save is current at once; the Brain screens are read-only
(see docs/brain-architecture.md, "Agent-kept"). Where this plan says propose /
accept, read "the agent saves / retires".

## 0. Principles

1. **FlowDesk has no AI inside.** It is the backend: tools, accounts, storage,
   background jobs. Every bit of thinking (summaries, learnings, decisions) is
   done by whichever agent is connected over MCP, and written back through
   Brain tools.
2. **The Second-Brain pattern, made automatic.** The user's Obsidian vault
   (`E:\Claude Workspace\Second-Brain`) works because agents follow
   `AGENTS.md` → read `hot.md` + `index.md` at start → append `log.md` and
   update `hot.md` at the end. That relies on the agent remembering. In
   FlowDesk the server does the bookkeeping itself, so it happens even when
   the agent forgets.
3. **Facts are never overwritten.** A changed fact supersedes the old one with
   dates (when it was true, when Brain learned it), so history stays readable.
4. **Local and private.** Everything lives in `userData/brain/`. Exports and
   reports stay masked. Brain never posts; outbound actions keep their
   approval rules.

## 2. Sessions: start, capture, wrap-up

- **Session = one MCP connection.** Each MCP server process gets a session id
  when it connects; FlowDesk notes the client name and start time.
- **Start:** `brain_start {platform?, brand?}` returns `AGENTS.md` rules (short
  form), `hot.md`, and a briefing (§3.4). Also offered as an MCP prompt
  (`/flowdesk:start`, shows up as a slash command in Claude Code) and as an
  MCP resource (`flowdesk://hot`). If a session calls other tools without
  `brain_start`, the first result carries one line: "call brain_start for
  context".
- **Capture (automatic):** every tool call in the session is recorded in the
  ledger (§3.3): writes in full (masked), reads as one summarised line.
- **Wrap-up:** `brain_wrap {summary, decisions?, next?}` writes the agent's
  `## Handoff` into `hot.md` and the log entry. Offered as prompt
  `/flowdesk:wrap`. **If the session ends without it** (the MCP process exits),
  FlowDesk still writes the log entry from the captured calls, marked "no
  handoff".

## 3. What Brain stores

Memory kinds, from agent-memory research (Letta's core/archival tiers, Zep's
episodes → facts with validity dates):

| Kind | Meaning | FlowDesk store |
|---|---|---|
| Core | always in context | `AGENTS.md` + `hot.md` + profile, ~1–2k tokens |
| Episodic | what happened | sessions, ledger events, job runs |
| Semantic | what is true | profile, brands, accounts, content, contacts, facts |
| Procedural | how to do it | skills, workflows, rules, accepted learnings |

### 3.1 Records and fields

| Record | Fields |
|---|---|
| **Profile** | name, roles, positioning, skills, goals (dated), languages/tone, working style, hard rules |
| **Brand** | id, name, niche, audience, offers/products, voice, visual rules, links, goals, status. Starting set to confirm: Alpha Paws (TikTok cat videos), coloring books / Arcane Frames (Pinterest + Gumroad), Codveon (agency, LinkedIn), personal brand (AI Engineer). |
| **Account** | platform, slot id, masked handle, brand, purpose (main / test / warm-up), posting rules, daily limits, warm-up stage, health, last action |
| **Event** | at, session, platform, account, tool, action, outcome, target id + url, content id, error |
| **Content item** | id, brand, kind (pin / video / product / post), idea source, prompts, generator + job id, files, approvals, stage (idea → made → approved → scheduled → live → measured) |
| **Placement** | content id, platform, account, external id, url, scheduled at, published at |
| **Metric snapshot** | placement or account, at, views / likes / saves / clicks / comments / followers / sales |
| **Learning** | statement, evidence (content + metrics), scope (brand / platform), confidence, status (active / retired) |
| **Task / calendar item** | title, brand, platform, due, state, waiting on (user approval / login / quota) |
| **Contact** | platform, display name (local only), stage (lead / talking / client), last contact, next step |
| **Idea** | text, source (radar / trends / Reddit / manual), score, brand, status |

### 3.2 Facts with dates
Profile, brand and account fields keep `valid_from / valid_to` and
`recorded_at`. Updating "goal: 10k followers" to "goal: 50k" closes the old
value instead of deleting it; `brain_history` shows the timeline.

### 3.3 The ledger (automatic)
The gateway already appends write-like actions to `action-log.jsonl`. The same
hook writes an Event row with session, account and target. Backfill from the
existing file. Tool: `brain_activity {platform?, account?, brand?, since?}`.

### 3.4 The briefing
`brain_briefing {platform?, brand?, account?}` → ≤1,500 tokens: rules, the
relevant brand and accounts, the last 7 days of activity, the next 7 days of
calendar, results waiting, things waiting on the user, failing tools and open
reports, top accepted learnings, and the skill to read next. `brain_start`
returns it.

## 4. Background jobs ("run in background")

Like a terminal command that keeps running and collecting while the agent does
something else.

- **Kinds:** research collection (TikTok radar, Pinterest trends and niche
  scans, Reddit search, LinkedIn search), metric pulls, bulk image generation,
  WhatsApp unread capture. None of these needs AI; FlowDesk runs them.
- **API:** `jobs_start {recipe, params}` → job id at once. Also `jobs_status`,
  `jobs_result {id, page}` (compact, paged) and `jobs_list`. Monitors run a
  recipe on a schedule.
  - This uses FlowDesk's own job ids — the pattern `chatgpt_image_jobs`
    already uses. The MCP "Tasks" feature from the 2025-11-25 spec is still
    experimental and moving, so it is mapped later, not depended on.
- **Engine:** the existing durable Brain job runner (recipes, steps,
  checkpoints, retries, leases, consent) — extended to the new recipes.
- **Inbox:** a finished job lands in the Inbox and in `hot.md ## Now`
  ("TikTok radar: 40 new videos ready"). The next agent session sees it in
  `brain_start`.
- **Agent packets (this replaces "chat digest").** When a job needs thinking
  (summarise chats, pick winners, propose learnings), it ends with
  `needs_agent: true` and a prepared work packet.
  - The connected agent calls `inbox_take`, does the thinking, and writes back
    with `brain_remember` / `brain_learning_propose`.
  - The results enter Review as candidates.
  - No model runs inside FlowDesk.
