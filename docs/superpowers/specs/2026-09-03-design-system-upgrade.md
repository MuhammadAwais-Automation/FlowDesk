# Studio design system — full upgrade spec

Date: 2026-09-03
Bar: Figma's properties panel (depth) · Canva's editor (fonts + text effects) · Photoshop's Layers and Character panels (layering + type)
Builds on: `2026-09-02-studio-ui-design.md`, `2026-09-02-reference-system.md`

## What is actually missing today

The shipped panel edits four things: position/size, radius, opacity + blend mode, and a
solid background colour. That is roughly 8% of what the three bar products expose. The
gap is not polish — whole categories are absent:

| Category | Today | Bar |
| --- | --- | --- |
| Typography | nothing | family, weight, size, letter-spacing, line-height, paragraph spacing, case, align, decoration, OpenType features |
| Fonts | whatever the document's CSS names | searchable picker over 100+ real bundled families |
| Fill | one solid colour | solid, linear/radial gradient, image |
| Stroke | nothing | width, colour, alignment |
| Effects | nothing | drop shadow, inner shadow, glow/neon, outline, blur, multiple stacked |
| Layers | a flat read-only tree | reorder, group, lock, hide, rename, per-layer opacity and blend |
| Agent tools | 11, none per-element | enough to build and edit any design conversationally |

## Decisions

### Fonts — Fontsource packages, latin subset, lazy `@font-face`

Measured on this machine: an installed Fontsource package is 92 KB (Outfit) to 619 KB
(DM Sans) with every subset and weight. Restricted to the latin subset, ~100 families
lands near 15–25 MB — acceptable for a desktop app, and the project **already uses
Fontsource** (`@fontsource-variable/outfit`, `dm-sans`, `jetbrains-mono`), so this is an
extension of an existing pattern, not a new dependency class.

Rejected: Google Fonts `<link>` tags. An Electron app should not depend on a CDN — the
poster generated during testing loaded Anton over the network, which means it renders
differently offline and the export silently loses the face.

**A generated catalogue** (`fontCatalogue.ts`) carries per-family metadata the picker and
the agent both read: family name, category (display / sans / serif / mono / script /
handwriting), available weights, variable-axis support, italic availability. Generated by
a script from the installed packages so it cannot drift from what is actually on disk.

**Lazy injection.** 100 families' `@font-face` rules loaded eagerly would stall both the
app and every artboard iframe. A font's face is injected the first time it is *used* —
once into the app for picker previews, once into the iframe for rendering — keyed by
family so a repeat use costs nothing.

### Typography — the full Figma set, plus OpenType

Family, weight, size, letter-spacing, line-height, paragraph spacing, alignment,
text-transform, font-style, text-decoration. OpenType features matter specifically because
the reference posters use a **swash** — and a swash is a separate glyph inside the font
file, unreachable without `font-feature-settings`. The panel exposes the features the
selected family actually declares, not a fixed list.

### Effects — Canva's vocabulary, expressed in CSS

Canva's effects decompose into CSS primitives already available:

| Canva effect | CSS |
| --- | --- |
| Shadow / Lift | `text-shadow` with offset, blur, colour |
| Hollow | `-webkit-text-stroke` with transparent fill |
| Splice | stroke plus an offset shadow |
| Echo | two or three offset copies at decreasing opacity |
| Neon | stacked `text-shadow` at increasing blur in the accent hue |
| Glitch | offset colour copies with `mix-blend-mode` |
| Curve | SVG `textPath` — the one that is not a CSS property |

So the effects layer is a **preset vocabulary over a small primitive set**, not seven
unrelated implementations. Each preset is parameterised (offset, blur, colour, intensity)
rather than a fixed look, which is what makes it editable afterwards.

### Layers — Photoshop's model, mapped onto the DOM

Photoshop's panel is: blend mode, opacity, fill opacity, lock, groups, clipping masks.
The DOM gives us all but fill opacity and clipping masks directly — reorder is sibling
order, group is a wrapper element, hide is `display`, lock is an app-level flag (the
document has no concept of it, so it lives in the editor's own state), opacity and blend
are CSS. Clipping masks map to `mask-image`; fill-vs-layer opacity has no CSS equivalent
and is deliberately out of scope.

### Agent tools — read/write parity with the panel

Every control the panel exposes gets a tool, because the whole architecture rests on the
panel and the agent sharing one model. The agent additionally gets what a human gets from
the canvas: list, select, group, reorder, duplicate, delete.

## The three agent-native features

These exist only because an agent is a first-class editor. No manual tool has them,
because they would be pointless without one.

### 1. Design Lint

`studio_get_guide` made the rules readable. Lint makes them **enforced**: the current
artboard is checked against the rules continuously, and violations appear in a panel —
"three typefaces used, rule allows two", "texture opacity 0.16 reads as no texture",
"nothing bleeds off the canvas edge". Each violation carries a one-click *Fix with agent*
that sends the agent the specific rule and the specific node.

This closes the exact failure observed in testing: the guide existed, the agent read it,
and still shipped a poster with one typeface and a texture at 0.16 — the number the guide
explicitly warns about. Advice the model may ignore becomes a check it cannot.

### 2. Variant fan-out

One command produces N genuinely different artboards side by side — not N renders of one
layout, but N design directions from the same brief, generated in parallel. A human
cannot do this because their cost per variant is an hour; the agent's is one call.
Selecting a winner keeps that artboard and offers to delete the rest.

### 3. Design memory

Every time the user edits something the agent just produced, that override is a
correction. Design memory records the pattern — "always overrides the suggested hero size
upward", "always replaces the accent with their brand red" — and folds it into what
`studio_get_guide` returns next time. The guide stops being static and becomes the record
of this user's taste, learned from what they actually change rather than what they say.

## Success criteria

1. Selecting text shows a searchable picker over 100+ real, offline-rendering families.
2. Every property the panel writes survives export and reload — no CDN dependency.
3. Layers can be reordered, grouped, locked, hidden, and blended, and the document HTML
   reflects it.
4. The agent can produce and then modify any of it conversationally, with byte-identical
   results to the panel doing the same edit.
5. Design Lint reports a real violation on the poster generated during testing, and its
   one-click fix resolves it.
